> **Trạng thái 2026-10-06:** Bước 1–3 ✅ xong (app 229 test, backend 19 test, thử E2E trên trình duyệt với backend + MongoDB chạy trên máy). Bước 4 (deploy) chờ bạn — hướng dẫn chi tiết ở `PTalk-be/README.md`.

**Mục tiêu:** Học sinh đăng ký bằng họ tên, username, mật khẩu, mã lớp. Đăng nhập trên máy khác vẫn có đủ XP, Leitner, huy hiệu, chuỗi ngày, nhiệm vụ… như cũ. Học offline vẫn được; có mạng lại thì tự đồng bộ.

## 1. Dữ liệu (MongoDB)

```
classes   { _id, code: "L2-T7" (duy nhất, chữ hoa), name, active: true, createdAt }
users     { _id, username (duy nhất, chữ thường), name, classCode, passwordHash, createdAt, lastLoginAt }
progress  { _id = userId, data: <khối Progress của app>, rev: số nguyên tăng dần, updatedAt }
```
- Index: `users.username` unique, `classes.code` unique.
- `progress.data` lưu nguyên khối JSON app đang có (`ptalk:v1:progress`) — server không cần hiểu bên trong.
- Dung lượng: ~20–50KB/học sinh → M0 (512MB) đủ vài nghìn em.

## 2. API

| Method | Đường dẫn | Việc | Trả về |
|---|---|---|---|
| GET | `/health` | Railway kiểm tra sống | `{ ok: true }` |
| POST | `/auth/register` | `{ name, username, password, classCode }` | `{ token, user }` |
| POST | `/auth/login` | `{ username, password }` | `{ token, user }` |
| GET | `/me` | Thông tin tài khoản | `{ user }` |
| GET | `/progress` | Tải tiến độ | `{ data, rev }` (chưa có → `data: null, rev: 0`) |
| PUT | `/progress` | `{ data, baseRev }` | `{ rev }`; nếu `baseRev` cũ → **409** `{ data, rev }` của server |
| POST | `/admin/classes` | Tạo mã lớp, header `x-admin-key` | `{ class }` |
| GET | `/admin/classes` | Liệt kê mã lớp + số học sinh | `[...]` |

- `/admin/*` dùng khoá bí mật `ADMIN_KEY` trong biến môi trường → bạn tạo mã lớp bằng một lệnh `curl`, tôi không phải chạm DB thật.
- Kiểm tra đầu vào bằng `zod`: username 3–20 ký tự `a-z 0-9 . _`; mật khẩu ≥ 6; tên 1–40 ký tự; mã lớp phải tồn tại và đang mở.
- Thông báo lỗi tiếng Việt: "Tên đăng nhập đã có người dùng", "Mã lớp không đúng", "Sai tên đăng nhập hoặc mật khẩu".

## 3. Bảo mật & tiết kiệm RAM

- Mật khẩu băm `bcryptjs` (thuần JS, không cần build native), cost 10.
- Phiên đăng nhập: JWT HS256 hết hạn 90 ngày, khoá `JWT_SECRET`.
- Chống dò mật khẩu: `express-rate-limit` — 10 lần đăng nhập / 15 phút / IP.
- `helmet`, CORS chỉ cho: web Vercel, `http://localhost:5173`, `capacitor://localhost` (iOS), `https://localhost` (Android).
- Driver `mongodb` thuần (không Mongoose) + `NODE_OPTIONS=--max-old-space-size=128` → mục tiêu ~80–120MB RAM ≈ 1–1,5 USD/tháng trên Railway.
- Atlas Network Access: Railway Hobby không có IP cố định → mở `0.0.0.0/0`, bù bằng mật khẩu DB dài ngẫu nhiên.

## 4. Đồng bộ ở app (offline-first)

- App vẫn đọc/ghi tiến độ trên máy như bây giờ (nhanh, chạy offline).
- **Đẩy lên:** mỗi lần lưu tiến độ → đánh dấu "chưa đồng bộ" → chờ 3 giây yên → `PUT /progress`. Mất mạng thì giữ dấu, thử lại khi có mạng / mở lại app / app quay lại từ nền.
- **Tải về:** khi đăng nhập, khi mở app, khi app quay lại từ nền → `GET /progress` → gộp với bản trên máy.
- **Xung đột (2 máy cùng học):** server từ chối bản cũ (409) → app gộp rồi gửi lại. Hàm gộp `mergeProgress(a, b)` (thuần, có test):
  | Phần | Quy tắc gộp |
  |---|---|
  | `phrases` (Leitner) | mỗi cụm lấy bản có `last` mới hơn |
  | `xp` | lấy số lớn hơn |
  | `bestScores` | lớn hơn theo từng trò |
  | `missions` | OR theo từng ô (đã xong ở máy nào cũng tính) |
  | `badges` | hợp lại, giữ thời điểm mở sớm nhất |
  | `streak` | `lastDay` mới hơn; cùng ngày lấy `count` lớn hơn |
  | `daily` | cùng ngày: lớn hơn theo từng bộ đếm, hợp danh sách; khác ngày: ngày mới hơn |
  | `stats` | lớn hơn theo từng trường, hợp `playedByTier` |
  | `name` | luôn lấy từ tài khoản |
- **Dữ liệu cũ trên máy (trước khi có backend):** lần đăng ký/đăng nhập đầu, tiến độ sẵn có được gộp vào tài khoản → không mất XP.
- **Đăng xuất:** đẩy nốt dữ liệu chưa đồng bộ (báo nếu đang offline), rồi xoá tiến độ trên máy để người sau dùng máy không thấy dữ liệu cũ.

## 6. Các bước thực hiện

### Bước 1 — Hàm gộp tiến độ (app) · ≈ 0,5 ngày
- `PTalk-app/src/lib/merge.ts` + `tests/merge.test.ts` (mỗi quy tắc ở bảng trên một test, thêm test "gộp 2 lần ra cùng kết quả").

### Bước 2 — Backend `PTalk-be` · ≈ 1 ngày
- Khung: `package.json`, TypeScript, `src/index.ts`, `src/app.ts` (tách app để test), `src/db.ts`, `src/auth.ts`, `src/routes/{auth,progress,admin}.ts`, `.env.example`.
- Build bằng `tsc`, chạy `node dist/index.js`.
- Test: `vitest` + `supertest` + `mongodb-memory-server` (DB ảo, không cần Atlas): đăng ký/trùng username/sai mã lớp/đăng nhập đúng-sai/token hết hạn/progress 409/admin sai khoá.
- `docker-compose.yml` chạy MongoDB trên máy để thử tay.
- `README.md`: chạy local, biến môi trường, deploy Railway, tạo mã lớp bằng curl.

### Bước 3 — App: đăng nhập + đồng bộ · ≈ 1–1,5 ngày
- `src/lib/api.ts` (gọi API, `VITE_API_URL`), `src/lib/auth.ts` (token, user — lưu qua lớp `storage` để app iOS/Android giữ bền), `src/lib/sync.ts` (đẩy/tải/gộp/thử lại).
- Màn `src/pages/Auth.tsx` thay `Welcome` trong `NameGate`; nút tài khoản + đăng xuất ở trang chủ.
- Test: `tests/sync.test.ts` (fetch giả): đẩy sau 3 giây, offline giữ dấu, 409 thì gộp và gửi lại, đăng nhập gộp dữ liệu cũ.
- Thử tay: web local + backend local (Docker), 2 tab trình duyệt như 2 máy.

### Bước 4 — Deploy · ≈ 0,5 ngày (cần bạn thao tác)
1. **Bạn:** tạo cluster Atlas M0 (AWS Singapore), user DB, Network Access `0.0.0.0/0`, lấy chuỗi kết nối.
2. **Bạn:** tạo repo GitHub cho `PTalk-be`, push (tôi không push), nối Railway → service mới, đặt biến môi trường: `MONGODB_URI`, `JWT_SECRET`, `ADMIN_KEY`, `CORS_ORIGINS`, `NODE_OPTIONS`.
3. **Bạn:** tạo mã lớp đầu tiên bằng lệnh curl tôi soạn sẵn.
4. **Bạn:** Vercel → thêm `VITE_API_URL` = địa chỉ Railway, deploy lại web.
5. **Tôi:** build lại app iOS với `VITE_API_URL`, thử đăng ký/đăng nhập trên simulator và web thật.

**Tổng: ≈ 3–4 ngày.**
